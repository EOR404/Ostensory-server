导入：从迁移包恢复

会替换当前站点数据

导入会先完整备份当前数据到数据目录旁边（Docker 等场景为配置的迁移状态目录），然后替换数据库、图片、密钥和设置。导入成功后旧登录会话会失效，需要使用迁移包里的管理员账户重新登录。

  • 只接受本程序导出的 .tar.gz / .tgz 迁移包。
  • 导入前会校验清单、文件 SHA256、数据库完整性和外键；任何一项失败都不会改动当前数据。
  • 导入过程中站点进入维护模式。若进程中断，下次启动会自动从导入前备份恢复；若自动回滚也失败，服务会停止接受请求，需要保留备份和标记后重启。
  • 迁移包里的后台路径、站点设置和管理员账户会一并恢复；导入前请确认你知道包内管理员账户和密码。
  • 当前数据备份会保留在 *.pre-migration-* 目录（默认在数据目录旁边；配置迁移状态目录时优先放该目录），备份同样包含密钥和账户信息；确认导入无误后可手动删除。导入进行中不要改 OSTENSORY_MIGRATION_STATE_DIR，也不要删除恢复标记或备份。

{% if max_archive_mb %}单包大小上限约 {{ max_archive_mb }} MB。{% else %}应用层不设置单包大小上限，实际上限由服务器磁盘剩余空间和反向代理的请求体限制决定。{% endif %}上传、解压和校验期间站点仍可用；进入维护模式后会先做完整备份，再替换数据，数据量大时备份本身也会持续一段时间。导入过程会临时占用“上传包 + 解压包 + 导入前备份”的空间，请预留足够磁盘。

迁移前检查

  • 目标服务器必须使用相同或更新的代码版本；迁移包只恢复数据，不替换程序代码。
  • 目标服务器磁盘至少预留“当前数据 + 迁移包解压后数据”的空间，导入还会再保留一份导入前备份。
  • 如果目标环境通过 OSTENSORY_MASTER_KEY 指定主密钥，它必须与迁移包内主密钥一致，否则会拒绝导入。
  • 远程存储里的图片会被转存到本机；迁移完成后旧远程服务即使下线也不影响已有图片。
  • 迁移不会自动修改反向代理、域名、HTTPS 证书或 Docker 挂载，这些仍需单独配置。
